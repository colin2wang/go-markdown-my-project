# 页面重设计方案
先诊断当前页面的问题，再给出重设计后的完整布局。
---
## 1. 现状问题诊断
| # | 问题 | 具体表现 |
|---|---|---|
| 1 | **纵向长页堆叠** | 项目列表、导出、结果全部塞在一页，滚动距离长，功能边界模糊 |
| 2 | **文件列表是平铺的不是树** | `src/config.rs`、`src/main.rs` 各自成一行，看不到目录层级，无法折叠 `src/` 整个目录 |
| 3 | **勾选框怪异居中** | 每行 checkbox 居中对齐，参差不齐（截图中最明显的问题），应左对齐形成整齐一列 |
| 4 | **三段各占一屏** | 大量留白，信息密度极低；文件列表区高度固定但内容只占右侧一小条 |
| 5 | **缺少关键功能入口** | 没有敏感信息扫描（需求 99！）、没有 token 估算、没有导出预览 |
| 6 | **结果展示简陋** | 黑底条里三行小字，应做成结果卡片 + 操作按钮 |
| 7 | **语言下拉含义不清** | 导出区的「语言：全部」实际是按文件类型过滤勾选，命名和位置易误解 |
| 8 | **项目管理与导出耦合** | 点卡片上的「导出」后下方内容整体替换，用户失去“我在哪”的上下文 |
---
## 2. 新信息架构：拆成两个视图
```
App
├── 视图A：项目管理页（/projects）
│     管理配置的增删改 + 扫描预检，不承载导出
│     卡片上的主按钮 = [进入工作台 ▸]
│
└── 视图B：工作台页（/workbench?project=xxx）
      三栏布局，所有导出相关操作都在这里完成
```
**导航方式**：顶部 Tab（`项目管理 | 工作台`）或左侧窄边栏；从项目卡「进入工作台」= 路由跳转并携带项目 id，浏览器式后退（面包屑 `← 返回项目列表`）。

### 4.1 左栏：项目 + 文件树（宽 320px）
替换现在的平铺列表：
```
── 文件 (13/13) ──────────
[🔍 搜索文件…]  [全选][反选][仅代码]
▾ 📁 src                    ← 目录行：可折叠、三态勾选
│   ☑ main.rs        5.1 kB
│   ☑ config.rs      4.5 kB
│   ☑ language.rs    0.9 kB
│   ☑ logger.rs      0.8 kB
│   ...
▾ 📁 projects
│   ▾ 📁 …
☑ cargo.toml        0.4 kB
☑ log4rs.yml        0.9 kB
☑ languages.yml     0.2 kB
─────────────────────────
 13 文件 · 37.4 KB · ≈8,600 tokens
```
- **树形结构**：按 `/` 分组构造层级；目录行带 ▾/▸ 折叠；勾选目录 = 级联全选，半选显示横线态。
- **全部左对齐**，checkbox 与图标、文件名构成一条纵线；文件大小右对齐灰色小字。
- 顶部三个快捷按钮沿用你已有的「全选/全不选」逻辑，追加「仅代码文件」（按语言映射过滤）。
- 底部统计条实时汇总勾选项。
- 目录/文件行高统一 28px，`size="small"` 密度。
### 4.2 中栏：导出选项（宽 300px）
**导出模式**——改为竖排单选卡片（你已有模式下拉，升级为卡片可获得描述文案空间）：
```
┌────────────────────────┐
│ ◉ 📄 完整代码           │  ← 选中：蓝色边框+浅蓝底
│   文件树 + 全部文件代码 │
├────────────────────────┤
│ ○ 🗂 文件名清单         │
│   仅文件树与路径列表    │
├────────────────────────┤
│ ○ 🔎 符号目录           │
│   文件名 + 方法/类名    │  ← 此卡右下角小字: 启发式解析
├────────────────────────┤
│ ○ ✍️ 签名导出           │
│   文件名 + 函数完整签名 │
└────────────────────────┘
```
**敏感信息过滤**（新增，需求 99 的入口）：
```
── 敏感信息过滤 ──
[✓] 导出时自动剔除密码/密钥
策略:  [占位符替换 ▾]
替换为: [REDACTED        ]
[ 🔍 扫描敏感信息 ]        ← 次级按钮，点击后 loading
结果芯片（三态）:
  ✓ 未发现敏感信息        （绿底绿字）
  ⚠ 发现 3 处  [查看 →]   （橙底橙字，点击右侧弹抽屉）
  ○ 尚未扫描              （灰）
```
敏感抽屉内容（点击「查看」弹出，宽 480px）：
```
┌─ 敏感信息命中 (3) ─────────────────┐
│ lib/auth.rs : 42  [api_key]        │
│   sk-abc1••••••••xyz      [误报🚫]  │
│ config.yml : 8    [db_url]         │
│   mysql://ro••••••••@10.0…  [误报🚫]│
│                                    │
│ 标为误报的条目导出时保留原文         │
│                    [知道了]         │
└────────────────────────────────────┘
```
**大小控制**：token 分片开关 + 数值输入，开启后显示「预计切成 2 片」。
### 4.3 右栏：结果 / 预览（弹性宽度）
**导出前**（占位态）→ 显示**导出内容大纲预览**：
```
── 内容预览 ──────────────────
# 项目文档 for Markdown My Project
├─ ## 项目文件树
├─ ## 项目文件 (13)
│   ├─ ### 文件: cargo.toml
│   ├─ ### 文件: log4rs.yml
│   ├─ ### 文件: src/config.rs
│   └─ …
[i] 当前模式: 完整代码 · 敏感过滤已开启
```
按当前勾选 + 模式实时生成（纯前端拼接标题层级即可，不需要后端）。
**导出后** → 切换为结果卡片（替换现在的黑色横条）：
```
┌─── ✓ 导出成功 ──────────────┐
│                             │
│  输出文件  output\markdown_ │
│           my_project.md     │
│  字符数    33,820           │
│  ≈ Token   8,600            │
│  耗时      2 ms             │
│  脱敏      0 处             │
│                             │
│  [📂 打开文件] [📋 复制全文] │
│  [📂 打开目录] [↻ 重新导出]  │
└─────────────────────────────┘
```
失败时红框卡片 + 错误信息 + 重试按钮。
### 4.4 底部状态操作条（新增）
固定底栏，替代现在悬在页面中间的「执行导出」按钮：
```
┌────────────────────────────────────────────────────────────────┐
│ ● 就绪    13 文件 · 37.4 KB · ≈8,600 tokens   [预览] [执行导出▸]│
└────────────────────────────────────────────────────────────────┘
```
- 左侧：勾选统计随勾选实时刷新（替代中栏底部的重复统计，二选一即可）。
- 右侧：`预览`（次按钮，生成完整 md 到临时文件并打开）+ `执行导出`（主按钮）。
- 导出中变为：`⏳ 正在导出… 8/13 读取 src/main.rs` + 内联进度条。
- 若开启了敏感过滤但**尚未扫描**，点导出时弹确认框：`尚未扫描敏感信息，建议先扫描 [扫描并继续] [直接导出] [取消]`。

## 5. 具体修复清单（对照现有代码）
| 优先级 | 改动 | 做法 |
|---|---|---|
| **P0** | checkbox 左对齐 | 文件行改为 `display:flex; align-items:center; gap:8px`，去掉居中；行结构：`checkbox · 图标 · 名称 ·(flex:1) · 大小` |
| **P0** | 平铺列表 → 树 | 按 `relPath` 的 `/` 分段构造树数据，目录节点可折叠；勾选级联 |
| **P0** | 页面拆分 | 项目列表与工作台拆成两个视图/路由；工作台改为三栏 grid：`grid-template-columns: 320px 300px 1fr`，高度 `calc(100vh - topbar - statusbar)`，各栏内部独立滚动 |
| **P0** | 结果区重做 | 黑色横条 → 右栏结果卡片 + 操作按钮（打开文件/复制） |
| **P1** | 新增敏感扫描 UI | 中栏过滤区 + 结果抽屉 + 导出前未扫描确认框 |
| **P1** | 新增 token 估算 | 估算函数（ASCII 4 字符 ≈1 token，中文 1 字 ≈1 token），勾选变化 300ms 防抖刷新左栏底部与状态条 |
| **P1** | 模式改单选卡片 | 下拉 → 竖排卡片组，带描述文案 |
| **P2** | 导出前大纲预览 | 右栏占位态实时渲染标题层级 |
| **P2** | 「语言：全部」改造 | 移入文件树工具行改名「仅代码文件」过滤按钮，避免歧义 |
| **P2** | 历史 | 结果卡片下加「最近导出」小列表（最近 5 条，点击打开） |

## 7. 重设计后的用户流
```
项目管理页                     工作台
┌──────────┐   进入工作台    ┌─────────────────────────┐
│ 项目卡片  │ ─────────────→ │ ①树中确认/调整勾选          │
│          │                │ ②选导出模式                │
└──────────┘                │ ③(可选)扫描敏感信息→处理命中  │
                            │ ④底部[执行导出]             │
                            │ ⑤右栏结果卡片 → 打开文件     │
                            └─────────────────────────┘
```
相比现在：**从 1 页滚 3 屏 → 1 屏完成全部操作**；文件树可折叠、对齐正常；敏感过滤（需求 99）有了完整入口；导出结果可一键打开/复制。
建议按 P0 → P1 → P2 顺序改造，P0 三项（对齐、树、分栏）就能让页面脱胎换骨，P1 两项补齐需求 99 与 token 能力。
